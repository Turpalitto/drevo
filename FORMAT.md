# Формат архива «Корни»

Полная выгрузка — обычный JSON-файл. Он содержит все данные семьи, включая фотографии (в виде data URL), и может быть открыт без «Корней».

## Верхний уровень

```json
{
  "format": "korni-local",
  "version": 1,
  "rev": 12,
  "title": "Моя родословная",
  "demo": false,
  "people": [],
  "log": []
}
```

| Поле | Значение |
|---|---|
| `format` | Всегда `korni-local`. |
| `version` | Версия формата. Сейчас `1`. |
| `rev` | Номер ревизии: растёт при каждом сохранении, защищает от затирания. |
| `title` | Название архива, до 100 символов. |
| `demo` | `true`, если это демонстрационный пример. |
| `people` | Список людей, до 5000 записей. |
| `log` | Последние 100 действий: `{ at, text }`. |

## Человек

```json
{
  "id": 1,
  "uid": "11111111-1111-4111-8111-111111111111",
  "name": "Ахмед",
  "native": "Ахьмад",
  "nameVariants": "Ахмад, Ахьмад",
  "sex": "M",
  "birth": 1930,
  "death": 2001,
  "birthFull": "1930-05-12",
  "deathFull": "",
  "birthQ": "abt",
  "birthQ2": null,
  "deathQ": "",
  "deathQ2": null,
  "father": null,
  "mother": null,
  "teip": "",
  "tukhum": "",
  "birthPlace": "Беной",
  "birthPlaceNow": "",
  "deathPlace": "",
  "deathPlaceNow": "",
  "residence": "Беной, Грозный",
  "occupation": "чабан",
  "info": "",
  "notes": "",
  "source": "",
  "photo": "",
  "photoMeta": null,
  "spouses": [2],
  "unions": [],
  "events": [],
  "sources": [],
  "memories": [],
  "documents": []
}
```

- `id` — число, уникальное внутри архива. При импорте может пересчитываться.
- `uid` — стабильный идентификатор (UUID), не меняется при экспорте и импорте. Соответствует `UID` в GEDCOM 7.
- `sex` — `M`, `F` или `U` (не указан).
- `birth`, `death` — только год, целое число или `null`. `birthFull`, `deathFull` — полная дата `ГГГГ-ММ-ДД` или пустая строка.
- `deceased` — необязательный булев признак (`true`), если человек гарантированно умер, но годы жизни неизвестны. Предотвращает ошибочное маскирование старых предков при защите сведений о живых.
- `birthQ`, `deathQ` — точность года: `""` (точный), `abt` (около), `bef` (не позже), `aft` (не раньше), `between` (интервал). `birthQ2`, `deathQ2` — второй год интервала, иначе `null`. В GEDCOM это `ABT`/`BEF`/`AFT`/`BET … AND …`.
- `father`, `mother` — `id` родителей или `null`.
- `spouses` — массив `id` супругов. Связь хранится с обеих сторон.
- `photo` — уменьшенная копия, data URL (`data:image/...`), не больше 600 000 символов. Оригинал хранится отдельно (см. «Медиа»).
- Все строковые поля обязательны и могут быть пустыми, кроме `name`.

## Фото

```json
{
  "caption": "Ахмед, 1950-е годы",
  "date": "1950",
  "source": "Из семейного альбома",
  "mediaId": "img-…",
  "people": [2, 5]
}
```

`photoMeta` — `null`, если подписи и оригинал не заданы. `people` — `id` людей на снимке.

## Браки

```json
{ "spouse": 2, "from": "1955", "to": "1970", "note": "венчание в селе" }
```

`spouse` обязан входить в `spouses`. Годы — свободный текст, чтобы можно было написать «около 1955».

## События

```json
{ "id": "e-1", "date": "1944", "title": "Переезд", "place": "Казахстан", "note": "" }
```

`date` — свободный текст: «1944», «весна 1944», «до 1950». Точная дата не выдумывается.

## Источники

```json
{ "id": "s-1", "title": "Рассказ сына", "kind": "oral", "note": "" }
```

`kind`: `document` (документ), `oral` (рассказ), `assumption` (предположение), `other` (другое).

## Воспоминания

```json
{ "id": "m-1", "text": "Помню его голос.", "author": "Сын", "at": "2024", "audio": null }
```

`text` — расшифровка, её можно править. `audio` — `{ mediaId, fileName, fileType, fileSize, duration }` или `null`. Если есть запись, текст может быть пустым: расшифровку добавляют позже.

## Документы

```json
{
  "id": "d-1",
  "title": "Свидетельство о рождении",
  "date": "1930",
  "eventId": "",
  "note": "",
  "mediaId": "doc-…",
  "fileName": "svidetelstvo.pdf",
  "fileType": "application/pdf",
  "fileSize": 248000
}
```

`eventId` привязывает документ к событию человека (если событие удалено, описание остаётся).

## Медиа: оригиналы файлов

Уменьшенная копия фото лежит прямо в записи человека, а оригиналы фото, документов и аудиозаписей — в хранилище браузера (IndexedDB, база `korni-media-v1`). В JSON архива они не попадают: иначе файл разросся бы до сотен мегабайт.

Для переноса есть отдельная выгрузка «Скачать архив с оригиналами файлов»:

```json
{
  "format": "korni-archive",
  "version": 1,
  "exportedAt": "2026-10-17T10:00:00.000Z",
  "archive": { "format": "korni-local", "version": 1, "people": [] },
  "media": [
    { "id": "img-…", "name": "ahmed.jpg", "type": "image/jpeg", "size": 1843200, "at": "…", "data": "base64…" }
  ]
}
```

Такой файл восстанавливается тем же «Восстановить из JSON»: данные заменяются, оригиналы возвращаются в хранилище браузера. Обычная резервная копия JSON оригиналы не содержит — это указано и в интерфейсе.

## Ограничения

| Поле | Предел |
|---|---|
| Людей в архиве | 5000 |
| `name`, `native` | 180 символов |
| `nameVariants` | 300 |
| `teip`, `tukhum`, `birthPlace`, `deathPlace`, `birthPlaceNow`, `deathPlaceNow` | 120 |
| `residence` | 300 |
| `occupation` | 180 |
| `notes` | 10 000 |
| `source` | 3000 |
| Событий у человека | 100 |
| Источников у человека | 50 |
| Воспоминаний у человека | 50 |
| Документов у человека | 30 |
| Браков с датами у человека | 20 |
| Фото (уменьшенная копия) | 600 000 символов data URL |
| Оригинал одного файла | 10 МБ (фото, документ), 25 МБ (аудио) |

## Совместимость

- Архивы без полей `nameVariants`, `occupation`, `residence`, `events`, `sources`, `memories`, `documents`, `unions`, `photoMeta`, `birthQ`, `birthPlaceNow` читаются как пустые значения.
- GEDCOM-экспорт содержит `UID`, `FAMC`, приблизительные даты (`ABT`/`BEF`/`AFT`/`BET`) и завершается `0 TRLR`.
- Фотографии и документы в GEDCOM не выгружаются: формат их не поддерживает.

## Проверка копии

```bash
npm run verify:restore -- data/backups/korni-2026-10-17.json
```

Скрипт поднимает отдельный сервер во временном каталоге, загружает копию и сравнивает имена, `uid` и связи. Рабочая база не изменяется.
