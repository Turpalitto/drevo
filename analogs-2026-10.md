# Аналоги «Корней»: что перенести (обзор на октябрь 2026)

Исследование: какие открытые проекты решают те же задачи и что из их кода, модели данных и технологий имеет смысл перенести в этот репозиторий. Правок в код не вносил — это предложение.

## Что смотрел

| Проект | Что это | Чем полезен нам |
|---|---|---|
| **webtrees** (PHP, GPL) | Классический self-hosted веб-генеалогия | Эталонная **модель приватности**, «поиск дубликатов», источники и цитаты |
| **Gramps Web** (AGPL, FastAPI + Vue) | Современный веб-фронтенд к Gramps | **PWA и офлайн**, история правок с отменой, роли, встроенный GEDCOM 7, 7 календарей |
| **Topola** (TS + D3, v3.10.4, сентябрь 2026) | Библиотека отрисовки деревьев; движок новых диаграмм webtrees | **Схемы раскладки**: hourglass, fan chart, kinship; Playwright-скриншот-тесты |
| **gedcom.io / gedcom7code** | Официальные инструменты FamilySearch GEDCOM 7 | Парсеры (`js-gedcom`), валидаторы, тестовые файлы `maximal70.ged` |
| **node:sqlite** (Node 22.5+, RC с 25.7) | Встроенный SQLite | `STRICT`-таблицы, `PRAGMA`, `VACUUM INTO` |
| **Node 24 `node:zlib`** | Встроенная компрессия | Gzip, Deflate, Brotli **и Zstd** — без зависимостей |

## P1 — безопасность и сохранность данных

### 1. Гостевая ссылка отдаёт живых людей
`server.js:307–310` — по секретной ссылке уходит **весь архив**:
```js
return sendJson(res, 200, { title: archive.title, people: archive.people.map((p) => ({ id: p.id, name: p.name, sex: p.sex, birth: p.birth })) });
```
В webtrees живые по умолчанию **приватны**, мёртвые публичны, а при нехватке данных человек считается живым; Gramps Web фильтрует приватные записи «на уровне базы».
**Что перенести:** правило «живой ⇒ скрыт» в этот же маршрут: не отдавать людей без даты смерти, родившихся позже `текущий год − 110`, либо отдавать только ближайшее окружение выбранного родственника. Правка на ~10 строк, эффект — на порядок меньше утечки.

### 2. Локальный архив живёт в `localStorage`
`index.html:495–496` (`KEY`, `BACKUP_KEY`), запись — `index.html:641,663,670,1618,1648,1667,1704`. Фото хранятся как data URL до 600 КБ (`server.js:123`). Лимит `localStorage` — около **5 МиБ на origin**, дальше `QuotaExceededError` (именно поэтому мы уже добавили уведомление при сбое сохранения). IndexedDB/OPFS делят общий пул в **гигабайты**, поддерживают бинарные данные и `navigator.storage.persist()`, который защищает от вытеснения по LRU.
**Что перенести:** перенести сам архив в IndexedDB (async, Blob вместо base64 — ещё и −33 % размера), запросить persistent storage, в `localStorage` оставить только настройки интерфейса.

### 3. Пароль проверяется через голый SHA-256
`server.js:329`:
```js
if (!PASSWORD || !body.password || !sameHash(body.password, PASSWORD)) {
```
`sameHash` — это SHA-256 без соли и без вычислительной стоимости: не KDF, перебор дешёвый, а сам пароль лежит открытым текстом в переменной окружения.
**Что перенести:** `crypto.scryptSync` (встроен в Node, зависимостей не добавляет) + случайная соль в таблице `kv`; при первом запуске — автоматический апгрейд старого значения. Это ~15 строк и не меняет продуктовую модель «один семейный пароль».

### 4. Бэкап — дамп JSON вместо снимка базы
`server.js:64–78` (`backupDaily`) пишет `data/backups/korni-<дата>.json`. Для self-hosted SQLite отраслевой стандарт — `VACUUM INTO '/путь/copy.db'` (с SQLite 3.27): даёт **согласованный** один файл, который восстанавливается как есть.
**Что перенести:** `PRAGMA journal_mode = WAL` и `PRAGMA busy_timeout` при открытии (`server.js:27` — сейчас PRAGMA не выставляются вовсе) плюс ежедневный `VACUUM INTO` рядом с JSON-копией. JSON оставить: на него уже ссылается README и инструкция восстановления.

## P2 — генеалогические функции

### 5. Стабильные идентификаторы (`UID`) и GEDCOM 7
Экспорт объявляет `2 VERS 5.5` (`index.html:1410`), хотя GEDCOM 7 вышел ещё в 2021 и в 2026 это актуальная версия. Файлы 5.5.1, как правило, **не являются валидными** файлами 7.0. Ключевое для нас новшество — `UID`: наши `id` пересчитываются при каждом импорте (`server.js:101`, `Math.max(...) + 1`), поэтому личность человека между выгрузками не сохраняется.
**Что перенести (по возрастанию объёма):**
- `1 UID <uuid>` в каждую запись `INDI` на экспорте и чтение его на импорте — стабильная личность между файлами и будущими слияниями;
- `EXID` для внешних идентификаторов (FamilySearch и т. п.);
- проверку нашей выгрузки реальным валидатором (`gedcom.tools`, `ged-inline.org`, `js-gedcom`) — можно автоматизировать в тесте;
- `SNOTE` (общие заметки) и `GEDZIP` (`.gdz`) — только если будем упаковывать фото внутрь файла.

### 6. Приблизительные даты
Сейчас дата строго ISO (`birthFull`, `server.js:120` — регулярка `^\d{4}-\d{2}-\d{2}$`), а в реальных записях сплошь «около 1850», «до 1900». GEDCOM умеет `ABT`, `EST`, `CAL`, `BEF`, `AFT` и диапазоны `BET … AND …`.
**Что перенести:** одно поле-квалификатор рядом с годом. Для старых записей по Кавказу отдельно стоит подумать о юлианском календаре (Gramps Web поддерживает 7 календарей; полная поддержка нам не нужна).

### 7. Источники и цитаты — самый крупный функциональный пробел
У нас на человека одна строка `source` (`server.js:116`, до 3000 символов). В webtrees и Gramps источники и цитаты — объекты первого класса (`SOUR` / `PAGE` / `QUAY`), и именно на них держится доказательная генеалогия.
**Что перенести:** `sources: [{id,title,type,url}]` + у человека `citations: [{sourceId,page,confidence}]`. Это отдельная итерация, не правка «на вечер».

### 8. Поиск дубликатов
Единственная защита сейчас — проверка «имя + год рождения» при подтверждении заявки (`server.js:388`). У webtrees есть полноценный поиск дубликатов, у Gramps Web — массовое слияние.
**Что перенести:** отчёт «похожие записи» на клиенте: нормализация имён (ё→е, й→и, регистр, пунктуация) + расстояние Левенштейна по имени и близость годов. Чистая функция, без зависимостей.

### 9. PWA и офлайн
Gramps Web устанавливается на домашний экран и работает как приложение. Наш клиент — один HTML-файл, и это идеальная почва для `manifest.webmanifest` + service worker.
**Что перенести:** кэш оболочки и установка на телефон; плюс `navigator.share` для ссылки-приглашения. Service worker — платформенный API, правило «без сторонних библиотек» не нарушает.

## P3 — технологии и производительность

### 10. Сжатие ответов
`index.html` — **119 689 байт**, отдаётся без сжатия (`server.js:270–273`). В Node 24 `node:zlib` умеет Gzip, Deflate, Brotli и **Zstd**.
**Что перенести:** предсжатый в памяти буфер + `Content-Encoding` и `Vary: Accept-Encoding` (порядок величины: 117 КБ → ~25–30 КБ), а также `ETag`/`If-None-Match` для `/` и `/assets/*` — сейчас у ассетов только `Cache-Control`.

### 11. Схема БД: миграции и `STRICT`
`server.js:28–30` — только `CREATE TABLE IF NOT EXISTS`, версии схемы нет. Официальный пример Node использует таблицы `STRICT`.
**Что перенести:** лестница миграций на `PRAGMA user_version` + `STRICT` в новых таблицах. Иначе первая же смена схемы станет болезненной.

### 12. Схемы дерева: hourglass и веерная диаграмма
Topola (движок новых диаграмм webtrees) даёт Ancestors, Descendants, **Hourglass**, Relatives, Fancy, Kinship; веерная диаграмма есть в Gramps Web и любима пользователями. Библиотеку тянуть не будем (у нас принцип «без зависимостей»), но идеи раскладки переносятся в наш SVG: hourglass вокруг персоны и веер предков.

### 13. Тесты
Topola гоняет Playwright-скриншот-тесты; мы проверяем клиент вручную через CDP-скрипты во временных файлах.
**Что перенести:** вынести чистые функции (сборка GEDCOM, `kinshipLabel`, `parseArchive`) в модуль и покрыть снапшот-тестами встроенного `node:test` (снапшоты есть с Node 22.3) — ровно так я вручную проверял GEDCOM в прошлой итерации. Playwright как dev-зависимость правила рантайма не нарушает.

## Что переносить НЕ стоит

- **Многопользовательские аккаунты, роли, OIDC** (Gramps Web) — противоречит осознанной модели «один семейный пароль», тянет за собой БД пользователей и UI администрирования.
- **DNA, OCR, семантический поиск, AI-чат** — тяжёлые зависимости и внешние сервисы.
- **Исторические карты и OpenHistoricalMap** — внешние тайлы, ломают офлайн и «без зависимостей».
- **Полная модель Gramps** (события, места и источники как отдельные записи) — это переписывание ядра; оправдано только если архив вырастет в настоящую исследовательскую базу.
- **Topola/d3 как зависимость** — берём идеи раскладки, а не библиотеку.

## Требует проверки

- **Статус `node:sqlite` в нашем образе.** Официальная документация: «Stability 1.2 — Release Candidate» начиная с v25.7.0; в Node 24 модуль ещё экспериментальный. Проверить на `node:24-alpine` фактически. *Требует проверки.*
- **Валидность нашей текущей выгрузки GEDCOM.** Структуру я проверил вручную и автотестом, но через сторонний валидатор файл не прогонял. *Требует проверки.*
- **Реальные квоты IndexedDB на iOS Safari** — цифры из документации MDN, на живом устройстве не мерил. *Требует проверки.*
- **Выигрыш от сжатия** — оценка по размеру файла, не измерение после включения. *Требует проверки.*
